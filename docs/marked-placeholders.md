# 22 registered marks on pages that say they are not written yet

`fle` carries a VG Wort Zählmarke on 22 pages whose entire body says the
content is still to come. They are 215–216 bytes each. One reads:

> **Phase 5 (à venir).** Cette annexe sera remplie après l'écriture des 156
> unités, afin de pouvoir lier des passages concrets.

A registration asserts that a work exists. These pages state that it does not.

## Why this is not the same as "a short page"

VG Wort's Mindestumfang for a Text is 1,800 characters, and a stub below it is
a page that has not grown yet — arguably a timing problem. A placeholder is a
different thing: it is the author's own written statement that the work is
scheduled rather than done. A mark on it is not premature, it is unfounded.

## The scale

| | pages | marked |
|---|---|---|
| `fle` | 22 placeholders | **22** |
| `daf` | 18 placeholders | 0 |
| `efl` | 0 | 0 |

daf is the useful comparison: it has 18 placeholder pages and has registered a
mark on none of them. So this is not how the organisation works — it is one
repo's pattern, and it looks like marks were assigned by walking the content
tree rather than by asking which pages were finished.

Twenty of the 22 are `uebersicht.md` track-overview pages, one per track and
Klassenstufe, all created together and all still empty.

## What to do, and it is a decision not a fix

Two honest options, and they are the author's call because both cost something:

**Withdraw the 22 marks.** Correct and immediate, and it means 22 codes are
retired in T.O.M. — codes are drawn per work and a retired one is not reused.

**Write the pages.** They are track overviews and annexes; each needs 1,800
characters of real content. That is authoring work, and until it is done the
marks stay unfounded.

What must not happen is the third option, which is leaving them and hoping: the
marks are already registered, so the exposure exists now and grows with every
quarter's reporting.

Gate A18 fails on these, so the state cannot become invisible again.
